# 结对学习与 GitHub 记录规则

## 我们怎样完成每次学习

每次只推进一个可验证的小目标：

1. 我先说明这一小步完成后能看到什么。
2. 只讲马上要用到的概念和少量示例。
3. 你亲手写核心代码并运行。
4. 你把结果或报错告诉我，我们一起定位。
5. 功能通过后整理代码、提交 Git，并写三行复盘。

默认不会一开始就给出完整答案。遇到困难时按三个提示等级推进：

- 一级：指出问题所在和检查方向。
- 二级：给出伪代码或关键 API。
- 三级：给出最小可运行修复，并逐行解释。

## 每次提交的标准

- 一次提交只完成一件能说清楚的事。
- 提交前至少亲自运行一次。
- 提交说明使用简短中文，例如：`feat: 支持拖动宠物`。
- 不提交虚拟环境、缓存、系统文件和个人存档。
- 每完成一个阶段创建一个版本标签。

建议的提交类型：

- `feat`：新功能
- `fix`：修复错误
- `refactor`：功能不变的代码整理
- `test`：测试
- `docs`：文档或学习日志
- `chore`：环境和工具调整

## 开发日志模板

每次结束前在 `devlog/` 中记录：

```markdown
## 今天完成

- 

## 遇到的问题与解决方法

- 

## 我现在能解释的概念

- 

## 下一步

- 
```

## GitHub 展示目标

仓库最终应让陌生人快速看懂：项目解决什么问题、如何运行、关键功能如何演进、你遇到过哪些问题，以及你真正掌握了什么。学习日志追求真实和简洁，不写成每日作文。
